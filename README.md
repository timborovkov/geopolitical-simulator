# Geopolitical Simulator

An initial playable Rust geopolitical strategy game for macOS, Linux and Windows, starting on **1 January 2000**. Govern one of 15 countries through its institutions, fund public services, expand energy and food supply, manage debt and survive political transitions. Other governments act through the same command rules.

This is the first connected game slice of the research roadmap: **341 proposed requirements across 42 ordered systems**. It does not implement the full catalogue. See the [initial-game scope](docs/initial-game.md) for implemented loops, simplifications and remaining work.

## Play

Install [Rust through rustup](https://rustup.rs/) and a native linker: Xcode Command Line Tools on macOS, a C compiler/linker on Linux, or Visual Studio Build Tools with Desktop development with C++ on Windows. The committed toolchain selects Rust 1.99.1, rustfmt and Clippy. Linux desktop play needs an X11/Wayland session, libxkbcommon and a Vulkan or OpenGL-capable graphics driver; the simulation and terminal game need no graphics stack.

Launch the native desktop game:

```sh
cargo run -p desktop --release --locked
```

Choose a country, select **Sandbox** or the authored **Fiscal and supply crisis**, and click **Begin**. Advance a day, inspect households and accounts, preview a policy, secure consent, fund it and watch delivery. Space pauses/plays; F5 saves, F9 loads and N advances to the next important event. F1 opens rebindable controls and interface scaling; Escape pauses and returns to the map. The interface includes a situation brief, charts, pinned country comparisons, a guide and a five-year objective. Long advances run off the UI thread, can stop at day boundaries and respect important-event pauses. Elections and leadership changes continue country play.

Play in a terminal:

```sh
cargo run -p headless --release --locked -- --interactive --country GBR --seed 2000
```

Type `help`. For example:

```text
advance 1
households
budget
preview energy 1
enact energy 1
advance 100
status
ledger
save campaign.json
replay
quit
```

Run a reproducible scenario without interaction (also the default `cargo run` behavior):

```sh
cargo run --release --locked -- --country CHN --seed 2000 --days 1827 --verify
```

Add `--scenario crisis` to the headless command for the authored fiscal/supply-crisis campaign.

The desktop map supports country-shape selection, zoom at the pointer, focus-on-country, keyboard panning and dated approval/needs/debt overlays. Metric legends explain colour thresholds, release coverage and dates. Expand **Overlay reports — select a country** to inspect each published value/date/age and select a country; missing releases stay unknown. Debt percentages retain fixed opening annual GDP as their denominator. Separate **Lakes** and **Rivers** switches show 25 lake and 14 river features from pinned Natural Earth reference data; hover for source names and expand **Physical map sources** for provenance and coverage. These generalized features are independent of country selection and campaign rules. **Find lake / river** searches names, alternate labels and local source IDs, including Latin-accent variants. Choose a result or press Enter for a single match to show its layer and frame it on the map; the selected country and statistical overlay stay unchanged. Islands and interior holes are preserved in the supplied reference shapes; markers and search cover countries without shapes. Charts use actual release dates and provide hover, keyboard inspection and text values. Foreign reports expose published aggregates; private household accounts, treasury and AI traces stay within the controlled government.

Both clients load the same bundled content. Supply `--content path/to/pack.json` to either executable to use a validated local JSON pack. Unknown schema, broken references, invalid ranges and incompatible saves produce explicit errors.

## World and game data

The [initial content pack](data/initial-2000-technology-eligibility.json) seeds 15 countries, 34 parties/governing bodies, eight institutional configurations and seven policy programs. The roster includes the UK, US, France, Germany, Russia, China, India, Japan, Brazil, South Africa, Saudi Arabia, Iran, Cuba, North Korea and Myanmar.

**The default starter has 29 pinned World Bank-mirror observations: population for all 15 countries and GDP for 14. North Korean GDP and other economic values, household profiles, seats, ideology profiles and political rules remain explicitly authored.** The source inspector distinguishes the two; the primary data API has not been independently reconciled. Historical identity names form a limited starter curation. Royal, military and religious governing bodies are explicitly scenario abstractions. All future decisions and successor cabinets are simulated. See [data provenance and coverage](data/README.md). The map combines Natural Earth public-domain land, generalized lake/river features and reference country outlines for the 15 starters. Their source revisions and transformations are pinned; they are not a certified 2000 sovereignty/control layer or dated water-extent observations. Administrative regions remain absent.

Money is expressed in millions of constant-2000 USD-equivalent game credits. Displayed local currency codes are identity metadata; there is no currency exchange model yet. Stocks and realized daily flows are shown separately. Policy forecasts state their assumptions.

The illustrative base includes actual private income and excludes public/local service payments and benefits. Fiscal packages retain paid administration, protected implementation reservations, institutional review, calendar execution and actual dated programmes. Recurring purchases need daily cash; these plans are not hard appropriations. Plans still require ordinary legal backing, available implementation cash, review and actual delivery. This remains a bounded heuristic. The [carried-interest roster](data/initial-2000-interest-accrual.json) retains rules 17 without technology prerequisites, the [cash-management roster](data/initial-2000-cash-management.json) retains rules 16 and its earlier interest rounding, the [dated-debt roster](data/initial-2000-debt-maturities.json) retains rules 15, the [national-fiscal roster](data/initial-2000-fiscal-ai.json) retains rules 14 with its perpetual new loans, the [income-band roster](data/initial-2000-income-bands.json) retains rules 13, the [fiscal roster](data/initial-2000-fiscal-plans.json) rules 12, the [undertaking roster](data/initial-2000-undertakings.json) rules 11 and the [territorial roster](data/initial-2000-territorial.json) rules 10. Food and energy prices respond after daily settlement; food reprices part of household baskets and both indices affect import bills. Treasury separates physical need, affordable demand, delivery and reconciled stocks. Borrowing requests need the country's configured legal route and decision delay; pending funds are unavailable until approval rechecks backing, government continuity, credit headroom and the finite creditor's funds. Treasury shows cancellation, debt records and an explicit contested emergency route with political costs/cooldown. New default loans have authored 365-day principal maturities after actual disbursement at fixed 4% interest in reporting credits; opening calibration debt remains perpetual. Due principal uses uncommitted national cash after protected local claims and before interest/national purchases. Unpaid matured principal stays in debt and is retried without duplicate operating arrears. Voluntary redemption still pays oldest debt first; separate refinancing requires ordinary authority, credit headroom and finite creditor funds. Rules 14 and earlier retain perpetual new loans. This does not complete sectors, endogenous wages, inflation, banks, FX, defaults or constitutional institutions.

The optional [cash-management fixture](data/synthetic-cash-management-test.json) adds rules 16 and snapshot format 17. All preserved packs and campaigns retain their behavior.

Optional sovereignty-reference rules 19 require snapshot format 20; default and optional dated-technology rules 18 require snapshot format 19; preserved and optional carried-interest rules 17 require snapshot format 18; preserved and optional cash-retention rules 16 require snapshot format 17; preserved and optional dated-principal rules 15 require snapshot format 16; preserved national-fiscal rules 14 requires snapshot format 15; preserved and optional private-income rules 13 require snapshot format 14; preserved fiscal content/rules 12 requires snapshot format 13; preserved undertaking rules 11 requires format 12; preserved territorial rules 10 requires format 11; preserved observed/electoral rules 8 requires format 9; earlier cabinet content/rules 7 requires format 8; earlier commitment content/rules 6 requires format 7; earlier constitutional content/rules 5 requires format 6; earlier financing content/rules 4 requires format 5; the earlier market starter retains content/rules 3 and the classic starter retains content/rules 2. Without --content, loading resolves the exact saved hash against the current, earlier carried-interest, earlier cash-management, earlier dated-debt, earlier national-fiscal, earlier income-band, earlier fiscal, earlier undertaking, earlier territorial, earlier observed, earlier electoral, earlier cabinet, earlier commitment, earlier constitutional, earlier financing, earlier market and classic bundled packs, retaining the saved rules. Explicit --content selections stay pinned. Unknown packs require their original file rather than a substitute. Compatible formats 2 and 3 load without changing their files or ordinary campaign checksums. Rules-3 through rules-19 campaigns cannot be relabeled as older formats. Saving over a validated format-2 snapshot first archives its exact bytes to a unique `.format-v2-N` file; subsequent saves retain that archive. Recovery also preserves originals, including a selected backup before format conversion, before writing the campaign's supported format. Version-1 files remain unsupported and are rejected without modification. Replay re-executes player and explicitly marked developer commands alongside deterministic AI and approved-budget programme dispatch, checks commands in sequence and verifies the final state hash. Diagnostics identify the first differing command or final-state field; a final snapshot alone cannot establish the earliest divergent tick. Hashes detect accidental corruption; they are not cryptographic authentication.

Developer inspection is explicitly enabled with `--developer` on either executable. The desktop adds a paused developer inspector for the selected country; the terminal adds `dev-fields`, `dev-inspect COUNTRY` and `dev COUNTRY FIELD VALUE`. Inspection exposes live world truth, including private foreign accounts, and belongs to the trusted host. Bounded direct field edits bypass policy costs and delays, consume ordinary command IDs, and permanently mark the journal/save as developer-modified. Normal player and AI command entry points reject these edits. Marked campaigns remain marked when reopened without the flag and cannot receive ordinary mandate certification. Merely opening the inspector does not modify a campaign. This is a limited scenario tool, not the full content editor.

This checks document/register consistency, local Markdown links, whitespace, Rust formatting, Clippy with warnings denied, tests, Rust docs with warnings denied, workspace release builds (including desktop) and the headless replay runner and a worked recovery campaign that achieves the five-year mandate in all 15 seeded countries through ordinary validated commands.
